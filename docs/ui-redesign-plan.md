# MediaTagger UI redesign

## Direction

Compact media studio, dark first with full light-theme coverage. Preserve primary green
`#7CB87C` in dark mode and `#2D5A2D` in light mode. Neutral workspace, panels and controls;
4px control, 6px panel and 8px dialog corners; 14px body text and 36px standard controls.
The gallery is a contact sheet with restrained badges and green checked selection outlines.
Use system sans typography and monospace for paths and technical data.

## Stages

Each stage follows implement, inspect screenshots, fix, verify. Work in the current checkout.
No worktrees. Decision evidence is recorded in [ui-redesign-decisions.tsv](ui-redesign-decisions.tsv).

## Layout and compatibility

- Header contains identity, search and Settings. Second row contains media filters,
  favorites, tag browsing, bulk mode and thumbnail sizing. Status remains below the gallery.
- Bulk inspector is 360px at widths of at least 1000px and follows the gallery below that.
- Settings uses 200px section navigation, wrapping above content below 1000px. Sections stay
  mounted: Library/scanning, Appearance, Import/export, Duplicates, Danger zone.
- Preserve lightbox geometry, collapse/drawer behavior, keyboard shortcuts, native bounds,
  idle reveal, zoom and fullscreen. Native controls stay dark over video in both themes.
- Preserve command/schema contracts, query cache, summary/details boundaries, mutation
  ordering, search semantics, operation locks, confirmation gates and stored preferences.
- Keep lazy loading and state ownership. Localize new labels in all 11 languages.
- Keep modal focus, Escape priority, reduced motion and visible keyboard focus.

## Acceptance and evidence

Review gallery, search/suggestions, bulk inspector, tag list, lightbox, settings, duplicate
resolver and confirmations in both themes at 1440×900 and 1000×720. Check narrow lightbox
at 600px and 320px. Include empty/error/loading states, long filenames/tags, and English/Polish.
Exercise a temporary library above the 1,536-asset cache bound. Use only disposable media
for destructive verification and preserve dev/release profile isolation.

Run focused component tests while iterating, then frontend tests, lint, locale validation,
production build, Rust checks for native changes, and affected isolated desktop workflows.
Record commands, screenshot links, outcomes and limitations below. Native video pixels may
remain unverified under Xvfb; distinguish that from native control/bounds verification.

### Findings and limits

- The matrix exposed a real 1000px Delete click regression: WebKit focus scrolling moved
  the action rail between pointerdown and pointerup. The closed rail is now non-scrollable;
  actual pointer clicks and confirmation cancellation pass in both themes.
- Native decoded video pixels remain black under Xvfb on this host. Their appearance remains
  unverified; native control styling, bounds and playback interaction checks passed.
- Empty, invalid-search and corrupt-original states have desktop screenshots. Transient
  loading behavior is covered by existing component/workflow tests, not a dedicated screenshot.
- [Calculated contrast](../artifacts/ui-redesign/verification/contrast.json) for primary-button
  text is 7.28:1 dark and 8.04:1 light. Body/workspace and body/panel pairs also pass 4.5:1;
  this is a limited token check, not a full accessibility audit.
- An initial frontend run had an intermittent Video.js teardown exception; the next complete
  run passed without changing playback or its tests. Initial top-level redesign captures and
  earlier failed-run directories are diagnostic only; use the timestamped sets above.
- No run-specific `agent-transcripts/` directory was available. Independent review checked
  the decision trail against tool output, logs and screenshots instead.
